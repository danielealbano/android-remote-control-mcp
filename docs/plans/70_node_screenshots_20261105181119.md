# Plan 70: node screenshots

New tool `get_node_screenshots`: one JPEG per requested node, cropped from the screen, optionally scrolling the app to capture nodes whole. The PR is held for the next version: open it, never merge it.

Rules (owner decisions):
- **Parameters:** `node_ids` (required, 1 to 100 strings, no duplicates) and `allow_scroll` (boolean, default false).
- **Images:** the node's visible bounds cropped from a full-resolution screenshot, Privacy Mode masked first, scaled down to fit 700×700 (never up), JPEG 80. No padding, no annotation. Images come in request order.
- **`allow_scroll` false:** one read, one screenshot. A node not on screen gets no image. A node cut by its scroll container is captured as shown and marked partial.
- **`allow_scroll` true:** the app scrolls until every node is captured whole. A node longer than its container comes in up to 3 overlapping parts. New node ids are never reported: the description and the reply say ids changed.
- **Reply:** always one text item first, then the images. The text item holds:
  - `UNTRUSTED_CONTENT_WARNING` as the first line;
  - when anything scrolled: `The app was scrolled to capture the nodes: node ids have changed, read the screen again before using any node id.`;
  - one line per requested id, in request order, using the line formats below.
- **Line formats:** image numbers are 1-based and count the images only: image 1 is the first `ImageContent` after the text item. The tool description and the docs say so too.
  - `<id>: image <n>`
  - `<id>: image <n>, partial: cut by the edge of its scrolling container`: the full size proves the cut (regular views).
  - `<id>: image <n>, may be partial: it touches the edge of its scrolling container`: no full size to prove it (Compose and web nodes).
  - `<id>: images <a>-<b>: <k> overlapping parts, in order`; a single part uses `image <n>`. Either form may continue with the `partial` or `may be partial` wording after a comma, when the node is still cut on the other axis at a part. It may then end with `; its start was not reached`, then `; the node continues` or `; then it disappeared while the app scrolled` or `; then it changed while the app scrolled`.
  - `<id>: not visible: off screen`
  - `<id>: not found`
  - `<id>: not captured: <reason>`, where reason is one of: `it could not be shown on screen`, `it changed while the app scrolled`, `it disappeared while the app scrolled`.
- **Errors and logs:** only node ids and counts, never node text.

## Cut rule (pure)
- [x] New `services/accessibility/NodeCutRule.kt`:
  - `enum class Edge { TOP, BOTTOM, LEFT, RIGHT }`.
  - `data class ScrollReach(up, down, left, right: Boolean)` with `ScrollReach.of(container: AccessibilityNodeInfo)`. Use the compile-time int ids (`android.R.id.accessibilityActionScrollUp/Down/Left/Right`, `AccessibilityNodeInfo.ACTION_SCROLL_FORWARD/BACKWARD`), never the `AccessibilityAction.X` objects, which are null on the JVM.
    - Any directional action present → exactly those directions.
    - Otherwise BACKWARD → up + left and FORWARD → down + right. These are visual directions, as RecyclerView and AbsListView define them.
    - That fallback is narrowed to one axis by `collectionInfo`: `rowCount > 1 && columnCount <= 1` → vertical; `columnCount > 1 && rowCount <= 1` → horizontal; otherwise both axes.
  - `fullSize(node: AccessibilityNodeInfo, data: AccessibilityNodeData): Pair<Int, Int>?`
    - `getBoundsInParent` width and height, with `@Suppress("DEPRECATION")` (approved by the owner);
    - null when `data.webRole != null` (Chrome reports web units) or either side is ≤ 0 (Compose reports 0x0).
  - `data class ScrollContainer(val bounds: BoundsData, val reach: ScrollReach)`.
  - `cutEdges(node: BoundsData, containers: List<ScrollContainer>, fullSize: Pair<Int, Int>?, justShown: Boolean, movedTowardStart: Set<Edge>): Map<Edge, ScrollContainer>`. `containers` lists every scrollable ancestor in the parsed tree, nearest first, the node itself excluded; nested scrollers such as a carousel in a list need them all.
    1. No containers → empty.
    2. An edge is cut by the nearest container whose same edge has the same coordinate and whose `reach` allows that direction: TOP↔up, BOTTOM↔down, LEFT↔left, RIGHT↔right.
    3. If `fullSize` equals the node's visible width and height → empty. The full size only ever clears.
    4. If `justShown` and `fullSize == null`, keep only the edges on an axis where the node's visible extent equals the extent of the container that cuts it. In views and Compose, `ACTION_SHOW_ON_SCREEN` shows a fitting node whole, and a node that does not fit fills the container (web nodes never get `justShown`, see **Judging a target**).
    5. When `justShown`, the edges in `movedTowardStart` (TOP, LEFT or both, see **Moved**) are not cut. A show from below aligns the top of a node that does not fit in ScrollView, RecyclerView and Compose alike; a show from above aligns differently per framework, so nothing is dropped then.

## Drag gesture
- [x] `ActionExecutor`: `suspend fun dragAndHold(fromX: Float, fromY: Float, toX: Float, toY: Float): Result<Unit>`, plus companion constants `DRAG_MOVE_MS = 600L` and `DRAG_HOLD_MS = 300L`, as measured on the T70.
- [x] `ActionExecutorImpl.dragAndHold`:
  - `validateCoordinates` for both points;
  - a drag shorter than 2 × `ViewConfiguration.get(service).scaledTouchSlop` → `Result.failure(IllegalArgumentException(...))` without dispatching anything. It would not scroll, and its held end would make it a long press;
  - stroke 1: path from→to, `StrokeDescription(path, 0, DRAG_MOVE_MS, true)` (the last argument is `willContinue`, positional: Kotlin allows no named arguments on a Java constructor), dispatched through `dispatchGesture`;
  - on success, stroke 2: `stroke1.continueStroke(Path().apply { moveTo(toX, toY) }, 0, DRAG_HOLD_MS, false)`, dispatched the same way. The held end stops the content gliding after release; on the T70 a drag moved the content no further than the finger.
  - Both dispatches run under `withContext(NonCancellable)`: a cancelled call must never leave the injected pointer down between the strokes. That is bounded by the strokes plus one `GESTURE_TIMEOUT_MS` per stroke.
  - The service is taken once, before stroke 1 (`IllegalStateException("Accessibility service is not available")` when missing, as `dispatchSingleStrokeGesture` does), and both strokes go through `dispatchGesture` on it. So an `IllegalArgumentException` or `IllegalStateException` means nothing was dispatched; a dispatch failure is a plain `RuntimeException`.
  - Either failure is returned as is.

## Drag segment (pure)
- [x] New `services/accessibility/DragSegment.kt`: `data class DragSegment(val fromX: Float, val fromY: Float, val toX: Float, val toY: Float)` and `dragSegment(container: BoundsData, centre: Pair<Float, Float>, length: Float, direction: ScrollDirection, screen: ScreenInfo): DragSegment?`. Every drag of the session goes through it (parts and seek with length 3/4 E, alignment with length d; E is the container's visible extent on the axis).
  - **Direction:** `ScrollDirection` carries the axis and the way, as in the `scroll` tool: DOWN/RIGHT is forward (reveals content below/right), UP/LEFT backward.
  - **Allowed area:** the container's visible bounds inset by E/16 at each end on the axis, intersected with the screen shrunk by 1/8 of its size on each side. That is the margin of the `scroll` tool's largest preset at zero variance, and it keeps fingers out of the gesture-navigation zones.
  - **Segment:** clamped to the allowed span on the axis, centred on the given centre (the target's visible centre for parts and alignment; the container's centre for a seek), then shifted inside the allowed area.
  - **Cross axis:** that centre's cross coordinate, clamped into the allowed area.
  - **Empty area:** null, treated by the session as a failed drag.
  - **Finger:** a forward drag moves the finger toward top/left, a backward drag the opposite way, through `dragAndHold`.

  - `internal fun cropRect(bounds: BoundsData, bitmapWidth: Int, bitmapHeight: Int, screenWidth: Int, screenHeight: Int): CropRect?`: null when either screen side is ≤ 0; otherwise scales screen bounds to bitmap pixels, clamps to the bitmap, and returns null when the result is empty.
  - `fun crop(bitmap: Bitmap, bounds: BoundsData, screenWidth: Int, screenHeight: Int): ScreenshotData?`:

## Capture session
- [x] New `mcp/tools/NodeScreenshotSession.kt`, one instance per call.
  - Dependencies come in one `data class NodeScreenshotDeps` (detekt's `LongParameterList` ignores data classes): `AccessibilityTreeParser`, `AccessibilityServiceProvider`, `AccessibilityNodeCache`, `ActionExecutor`, `ScreenCaptureProvider`, `ScreenshotRedactor`, `NodeImageCropper`, `WebViewNodeMerger`, `PrivacyToolGate`.
  - The session takes the deps and a `read: () -> FreshRead`, which defaults to `getFreshRead` over the deps.
  - Split it into small classes or files as needed so detekt passes without new suppressions. A new file holding a single non-private top-level class is named after that class (detekt `MatchingDeclarationName`).
- [x] **Read index:** each read is indexed once:
  - id → `AccessibilityNodeData`;
  - id → parent id, from `CachedNode.parentId`;
  - live node → id, a `HashMap` keyed by `AccessibilityNodeInfo`, whose `equals` is the source node plus window.
- [x] **Targets:** resolved from the first read (data + live node). In each later read, a target is found again through its live node in the new index.
  - A target is "present" when its live node is in the read with the same `className`, `resourceId`, `text` and `contentDescription` as in the first read. Lists reuse rows, so a mismatch means another item.
  - **Re-identified:** when a target that is acted on (round head) is not present by its live node, it is looked up by content: the single node with the same `className`, `resourceId`, `text`, `contentDescription` and `webRole` among the descendants of its nearest last-seen container present in the read, that container found by its own live node. A match is adopted as the target's live node and data; no match or several → not present.
    - Compose gives a lazy-list item a new id when it comes back into view (`LayoutNode.onReuse` regenerates the semantics id), so the old live node is never found again.
  - Missing or mismatched targets are reported only when acted on (round head, parts flow): `not captured: it disappeared while the app scrolled` or `not captured: it changed while the app scrolled`. A pending target missing from a read is simply not captured from that read.
  - **Last seen:** for every target, keep the last read where it was present: its bounds, and its scrollable ancestors nearest first (its last-seen containers), each with its live node, bounds, reach and axis (vertical when its reach has up or down, else horizontal). Also keep, per axis, the direction of the first movement on that axis after that read: forward, backward, or unknown. Forward is a forward drag on that axis, or a show that moved its target's top up (left on the horizontal axis); backward the other way.
- [x] **Judging a target:**
  - not visible (`visible == false` or empty bounds) → off screen;
  - otherwise `cutEdges(...)` with its scrollable ancestors (bounds plus `ScrollReach.of` their live nodes) and `fullSize`. `justShown` and `movedTowardStart` apply only right after that target's own show, and never to a web node (`webRole != null`); otherwise they are false and empty. On the T70, Chrome's show did nothing for a node whose top was on screen, even one cut at the bottom (fitting or taller than the screen); a node whose top was off screen was scrolled into view (an off-screen paragraph was centred, a tall one cut at the top jumped to its start). So a web node's cut stays after its show, and the parts flow handles it.
  - Cut with a `fullSize` → the `partial` line; cut without one → the `may be partial` line.
- [x] **Capture**, given a fresh read and the targets to crop:
  - the mask, the bitmap copy, the crops and the encodes of each capture run under `withContext(Dispatchers.Default)`, as `docs/PROJECT.md` assigns screenshot encoding;
  - flagged bounds from `privacyToolGate.tree(webViewNodeMerger.merge(read.result)).flaggedBounds`;
  - `captureScreenshotBitmap(null, null)`;
  - `ScreenshotRedactor.mask` with `getScreenInfo()` sizes;
  - if the result is still a `HARDWARE` bitmap (nothing flagged), copy it once to `ARGB_8888`, so the crops do not each copy the hardware buffer;
  - one `cropper.crop` per target. A null crop → `not captured: it could not be shown on screen`, and no image number is used;
  - recycle each bitmap once, guarding identity with `!==` as `get_screen_state` does.
  - Capture failure → `McpToolException.ActionFailed("Screenshot capture failed")`. Privacy failures propagate, as in `get_screen_state`.
  - A failing mask, copy, crop or encode (any other exception) → `ActionFailed("Screenshot encoding failed")`, logged, as `get_screen_state` does; a `CancellationException` is rethrown as is.
- [x] **Settle**, then do a fresh read:
  - **After a show:** every 50 ms, `refresh()` the target's live node. Settled once its screen bounds are unchanged over 3 consecutive polls, or 1500 ms have passed, or `refresh()` returns false.
  - **After a drag:** a fixed `DRAG_SETTLE_MS = 500`. A held drag does not glide, but one that reaches the end of a list stretches it until release; on the T70 the stretch was gone 400 ms after release.
  - Every drag counted as dispatched (Scroll, step 5) is followed by its settle and a read, even when it failed, before anything is judged or captured. Only a refused drag has neither.
- [x] **Moved:** a show moved its target when its settled bounds differ from its bounds in the read before the show (views scroll instantly, before the first poll). `movedTowardStart` holds TOP when its top decreased and LEFT when its left decreased, each on its own.
- [x] **Show:** `performAction(android.R.id.accessibilityActionShowOnScreen)` on the live node. The return value is ignored: Compose always returns true, views return false when there is nothing to do.
- [x] **No scroll** (`allow_scroll` false):
  - judge every found target on the first read;
  - capture once for the on-screen ones, and only when there is at least one;
  - cut → the `partial` or `may be partial` line.
- [x] **Scroll** (`allow_scroll` true):
  1. On the first read, capture the on-screen targets with no cut edges together, when there are any.
  2. `pending` = the other found targets, ordered by window, then tree pre-order of the first read.
  3. **Round**, while `pending` is not empty. The head is the first of `pending`, and it always leaves `pending` in its round, so there are at most as many rounds as targets.
     - **Reach** the head:
       - Present in the current read → show it, settle, read.
       - Not present, even re-identified → seek it (Compose drops nodes scrolled fully out of view), up to 2 drags:
         - **Container:** its nearest last-seen container present in the current read, so a carousel dropped with its row falls back to the outer list. None present → `disappeared` with no drag.
         - **Direction:** opposite to the first movement on that container's axis after the target was last seen. A forward movement means it left by the top/left, so seek backward; a backward movement → seek forward. When unknown, backward if the target's last bounds were above/left of that container's last centre, else forward.
         - **Geometry:** `dragSegment` of 3/4 E on that container, on its axis, with its bounds from the current read. The last bounds serve only the centre fallback.
         - After each drag, settle and read, stopping once the target is present or re-identified; then show it, settle, read.
       - Still not present → `disappeared` or `changed`; next round.
     - **Judge** it with `justShown`:
       - off screen → `not captured: it could not be shown on screen`;
       - cut → the parts flow;
       - whole → go on.
     - **Align**, only when `pending` still holds other targets:
       - **Container:** walk the head's scrollable ancestors nearest first; the first whose reach has down aligns vertically, else the first whose reach has right aligns horizontally, else the alignment is skipped. E is its visible extent on that axis.
       - d = the head's top (left) − (container top (left) + E/16). When d ≥ E/8, drag forward with `dragSegment` of length d (clamped by it to what fits), then settle and read.
       - This brings the head near the top, so the targets after it come into view with it. A minimal show leaves the node against the far edge, which would cost one screenshot per target.
       - If the head is no longer whole afterwards, show it again, settle, read, and judge it again with `justShown`: off screen → `not captured: it could not be shown on screen`; missing or changed → the matching `not captured` line.
       - A refused drag skips the alignment; after a dispatched drag that failed, the round goes on from the read that follows it.
     - **Capture** the head, plus every other pending target that is present and whole in this read (judged with `justShown = false`); they all leave `pending`. The head is captured even if it is now cut, using its cut line.
  4. **Parts flow** for a target that is still cut after its show:
     - **Axis:** vertical when TOP or BOTTOM is cut, otherwise horizontal. The drag container is the one cutting that axis's edge (TOP/LEFT first).
     - **Drag:** `dragSegment` of 3/4 E on the drag container, centred on the target's visible centre.
     - **Back phase:** while TOP/LEFT is cut and fewer than 3 back drags: drag backward, settle, read, judge.
     - **Align:** before part 1, when TOP/LEFT is not cut and the target's top (left) is more than E/8 past the container's top (left) + E/16, align it with the round head's drag, then settle and read; no show follows, since the target is cut anyway. This happens after a back drag that went past its start, or a show from above that top-aligned it in RecyclerView; without it, part 1 would be a sliver.
     - **Parts:** capture one part, then while BOTTOM/RIGHT is cut and fewer than 3 parts: drag forward, settle, read, judge, capture. Each part's capture also takes the other pending targets that are present and whole in that read; they leave `pending`.
     - **Notes:** if TOP/LEFT was still cut at the first part → `; its start was not reached`. If BOTTOM/RIGHT is still cut at the last part → `; the node continues`.
     - **Gone mid-flow:** if the target disappears or changes after a part, keep the parts so far and end the line with `; then it disappeared while the app scrolled` or `; then it changed while the app scrolled`, in place of `; the node continues`. Before any part → `not captured: <reason>`.
     - **Failed drag:** ends its phase. In the back phase, the parts start from the read that follows it (the current read when it was refused); in the parts phase, the parts end at the last part and the notes follow the cut state at the last part.
  5. "Scrolled" is true once a drag was dispatched (whatever its result) or a show moved its target. A drag refused before dispatch does not count: a null `dragSegment`, or a `dragAndHold` failure that is an `IllegalArgumentException` (bad or too short) or an `IllegalStateException` (no service). Any other failure counts as dispatched.
- [x] **Time:** every wait is a cancellable `delay`, so a cancelled call stops between steps. There is no overall time cap: the owner accepted that 100 nodes can take tens of seconds.
- [x] **Error after scrolling:** when a `McpToolException` ends a call that has already scrolled, rethrow the same subclass with a space and the scrolled note of the reply appended to its message, the original as `cause`.
